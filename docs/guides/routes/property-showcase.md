## Overview

Standalone shareable landing page for a property. Hosts pick one of six animated templates (Aurora, Monolith, Editorial, Verso, Atlas, Haven), configure sections/copy/images/style/motion, and publish a link guests can open outside the marketing and operational shells.

While the page or its template chunk loads, guests see a full-bleed skeleton: header, hero, then stacked sections (a two-column block from `lg`).

**Shared engine:** the [[stay-guide|Stay Guide]] renders through this same template registry + shell + palette/typography/motion system. `ShowcaseData.pageKind` (`'showcase'` \| `'stay-guide'`) and `section.kind` discriminate; Stay-Guide-only kinds (`passCard` / `checkInDocuments` / `chapter` / `quickNav`) render via `templates/shared/StayGuideSections.tsx`. Showcase behaviour is unchanged.

## Host-facing knowledge

Showcase is a one-page link you can send to guests with your property’s photos, amenities, and booking CTAs. It is separate from the marketing listing page.

**Common host questions**

- Q: Where do I edit Showcase?
  A: Property → Public Pages → Showcase → Edit. Every plan can open the editor; saving needs Pro.
- Q: Why does the guest link show a plan message I can’t close?
  A: The live Showcase page isn’t available on this property’s plan. Guests see a short message and a **Home** link back to Explore — ask the host to upgrade or fix the link.
- Q: Why is the guest link “Not available”?
  A: Publish it in the Showcase editor. Draft showcases stay private.
- Q: Which plan includes Showcase?
  A: Pro and above (live page + save). Free can open the editor to explore.
- Q: Can I use my own uploaded photos beyond the gallery?
  A: Not yet — image slots pick from existing property media.
- Q: What’s the difference between Showcase and the Property listing?
  A: The listing lives in the marketing site with booking widgets. Showcase is a single scrollable landing page with its own look and motion, meant to share as a link.
- Q: Why don’t Parallax / Canvas do anything?
  A: Those switches only appear for templates that use them (for example Parallax on Aurora and Atlas; Canvas on most templates except Haven). Use Motion intensity Standard or Bold for parallax. If your device has “Reduce motion” turned on, heavy effects stay off.

## Guest behavior

- URL: `/properties/:propertySlug/showcase`
- Templates (distinct worlds):
  - **Aurora** — Outfit display, **layered spring parallax hero**, section scroll parallax, **frosted-glass header** (`backdrop-blur-xl`, translucent surface + soft elevation; pill nav; larger brand type), mesh canvas, sticky progress rail, stable hero CTAs, lift amenities
  - **Monolith** — Instrument Serif display titles, **Plus Jakarta sans header/nav**, ink canvas, grain + cursor spotlight, amenity marquee, animated stats; **brutalist header** — chromeless white type over hero, then **opaque** stone/ink bar with a **thick bottom rule** (no blur, sharp corners, underline nav) once hero scrolls past ~76px
  - **Editorial** — Cormorant display, warm cream paper, asymmetric collage hero, Embla testimonials; **magazine masthead** — fully opaque paper bar, **soft hairline rule** (palette ink at ~10% opacity), serif brand title, underline nav (no frosted glass)
  - **Verso** — kinetic lookbook. **Jost** heavy uppercase display, monochrome ground + one accent. Chromeless full-bleed hero with a Ken-Burns image and a **word-mask "rise into place"** title; a two-row **infinite marquee band** (property name / location / amenities, second row reversed); `NN`-numbered "plate" section headers with a **draw-in hairline rule**; About set as a large statement with **scroll word-fade**; amenities as a big numbered list that **slides in from alternating sides**; highlights as oversized **count-up** numerals; reviews on an auto-advancing **crossfade stage**; a **pinned horizontal-scroll gallery** (sticky viewport sized to the real scrollport — live or preview frame — vertical scroll scrubs a full-bleed one-up translateX strip + progress bar via `useShowcaseScrollProgress` `pin` mode); falls back to `ShowcaseGalleryCarousel` only for a single image; inverted full-bleed CTA with a mask-reveal heading + **fill-sweep** buttons. **Header:** true chromeless over hero (transparent + white type), then solid monochrome bar with thick rule + uppercase tracking nav. Own light + dark palette.
  - **Atlas** — cinematic dossier. **Space Grotesk** display + `font-mono` data, dark-first atmospheric **glass** palette. Hero: parallax + Ken-Burns image, drifting mesh canvas, vignette, blur-to-sharp title, and a **glass HUD** with coordinates + a live-ticking `Asia/Manila` clock. **Sticky "chapter" headings** (`§ NN` + title + draw-in accent rule) hold at the top while each section's content scrolls past. About includes an **At a glance** card: full-width **area** row (location value + `Area` label), then a **2×2 / 4-column** stat grid with the same value-on-top / label-below parsing as Highlights (`parseShowcaseHighlight`). Amenities as **glass tilt-cards**; highlights as glass tiles with **count-up** + a draw-in underline; gallery via **`ShowcaseGalleryCarousel`** (one image per slide); a **scroll-grown full-bleed map** that scales up + de-rounds as it enters the Location section; glass slide-in reviews; a glass CTA floating over an accent bloom. **Header:** heavy `backdrop-blur-2xl` HUD with accent color rail under the bar + mono uppercase nav. Own light + dark palette.
  - **Haven** — warm hospitality. **Fraunces** display + **Figtree** body, sand paper + soft shadows + pastel gradient blooms, rounded "postcard" cards, pill controls, eyebrow pills per section, a dashed **stamp badge** in hero + CTA, Fraunces drop-cap on About, rounded gallery + map. **Header:** inset **floating capsule** (`rounded-2xl`, soft elevation, not a full-bleed strip). Own light + dark palette.
- **Verso / Atlas / Haven** reuse the shared shell (header/footer/nav/scrollspy/theme toggle) and `ShowcaseGalleryCarousel`. Location uses `ShowcaseLocationPanel`; **Host** uses template-specific sections in `templates/shared/ShowcaseHostSections.tsx` (Verso / Atlas / Haven variants with chapter eyebrows). **Aurora / Monolith / Editorial** use their own host variants plus `ShowcaseLocationSection`. Host contact comes from property guest-contact settings; preview lorem + banner only when name/avatar/phone/email are all missing (`hasShowcaseHostContent`). On published (non-preview) pages these templates **collapse** a soft section (About / Amenities / Highlights / Reviews / Gallery / Location) that has no real content instead of rendering an empty band (`shouldRenderShowcaseSection`); preview/editor/embed still fill it with placeholders. Numeric highlight parsing is shared via `parseShowcaseHighlight` (leading number → big value + label; `"Up to 4 guests"` → `4` / `guests`; `"Check-in 2:00 PM"` → `2:00 PM` / `Check-in`; phrase highlights like `"Walkable neighborhood"` render as one line).
- Header: property logo + name (**logo/name click scrolls to top**); **light/dark theme toggle** in the header (live + Page Editor preview); **section links collapse to the hamburger** when the **full** property name + labels would not fit with comfortable gaps (`useShowcaseCompactHeaderNav` uses untruncated brand width + nav probe + comfort slack — prefers hamburger over ellipsizing the title; large desktops keep inline links; Page Editor mobile preview always uses the hamburger). Shared with Stay Guide via `ShowcaseShell`. **Per-template header chrome** (`showcaseHeaderChrome.ts` + `tokens.header` / `headerHero`) — not a shared translucent strip: **Aurora** frosted glass blur; **Monolith** opaque thick-rule brutalist (chromeless white over hero); **Editorial** opaque magazine masthead; **Verso** chromeless over hero → solid lookbook bar; **Atlas** HUD glass + accent rail; **Haven** inset floating capsule. **Mobile menu** (`ShowcaseMobileMenu` + `showcaseMobileMenuConfig.ts` + `showcaseMobileMenuTypography.ts`): full-viewport overlay with opaque panel painted from **showcase surface / ink / accent** CSS vars; link type uses **fluid body-scale sizing** (~16–21px via `--showcase-body-scale` + `cqw`, template-aware serif/caps tiers) instead of display headlines; sticky header **hides** while open (no double chrome). Always portaled to `document.body` above the pinned header. In Page Editor / embed the overlay is a **`motion` clip root** (`overflow: hidden`) **`position: fixed`** to the preview frame’s `getBoundingClientRect()` — panel slide/curtain `%` translates stay inside the phone frame; scroll lock uses `data-showcase-scroll-lock`; backdrop tap, menu close, or **Escape** closes; link navigation `flushSync`s close before scrolling. Per-template menu motion: **Aurora** — full-screen slide-down; **Monolith** — curtain clip-path; **Editorial** / **Haven** — bottom sheet slide-up; **Verso** — right drawer + indices; **Atlas** — glass fade/scale.
- **Color mode:** each template has its own light + dark token pair (Aurora: shadcn light / slate dark; Monolith: stone light / ink dark; Editorial: cream light / espresso dark). The **header theme toggle** picks light vs dark; guest choice persists in `localStorage` per property + template (editor preview toggles in-session only). **Readable ink scale:** `.showcase-scope` always gets soft semantic CSS vars (`--showcase-ink`, `--showcase-ink-muted`, `--showcase-ink-faint`, `--showcase-border`, plus mapped `--foreground` / `--muted-foreground` / `--border`) via `buildShowcasePaletteTones` / `buildShowcaseDefaultInkTones` — never pure white/black, and never the dashboard light muted color on a dark template page. Brand / Custom / Curated / From-photos also paint surfaces from the same tone builder. Preview **“Renders test data”** badges use accent-tinted ink (`ShowcasePreviewMockBanner`). **Atlas** / **Haven** alternating section bands (`sectionAlt`) and related chrome use relative tints so custom surfaces stay in-family.
- **Style controls** (Page Editor → Style): controls are **template-aware** via `showcaseEditorStyleFields.ts` — only options that affect the selected template are shown. Each Style field label has a **?** help tooltip (`FieldLabel`) with a short plain-language tip. Always: palette mode (**Default**, **Brand**, **Curated** brand-color presets, **Custom**, or **From photos**), type scale, motion intensity. **Default** keeps template surfaces and uses the property brand color as accent (no separate accent control). **Palette mode** dropdown shows color swatches beside each option — four overlapping circles (light surface, dark surface, light accent, dark accent). **Custom** (last item in the dropdown) opens an inline HSV picker (`ShowcaseCustomPalettePicker`) — drag saturation/brightness and hue to live-generate surfaces + accents via `buildShowcaseBrandPalette`; preview swatches update smoothly as the host picks. Stored as `palette.mode = custom` + `palette.customPaletteBase` (hex). Previews use live property brand / photo-extracted colors when available (`showcasePalettePreview.ts`, `PalettePreviewChip.tsx`). **Curated** presets (`showcasePresetPalettes.ts` + shared `brandColorPresets.ts`) mirror property **Brand color** swatches — **Coral**, **Amber**, **Lime**, **Emerald**, **Teal**, **Sky**, **Indigo**, **Violet**, **Fuchsia**, **Pink**, **Rose** — each generates a full showcase surface + accent pair via `buildShowcaseBrandPalette`; theme toggle selects light vs dark. Legacy saved ids (`warm`, `ocean`, `blush`, etc.) normalize on read. **Brand** uses the property's saved brand color; **From photos** samples gallery images. Conditional: **hero overlay** (Aurora / Monolith / Verso / Atlas full-bleed heroes — not Editorial collage or Haven postcard), **display font** (Aurora only), **parallax** (Aurora layered hero/sections + Atlas hero/map grow — hidden on other templates and when intensity is **Subtle**), **canvas background** (mesh/grain on Aurora / Monolith / Editorial / Verso / Atlas — not Haven). Applied inside `.showcase-scope` only. **From photos** samples up to 10 property images client-side (`showcaseMediaPalette.ts`): cream/sand/beige backgrounds drive surfaces; warm accent hues are preferred over small UI colors. **Parallax** and **canvas** honor the toggles in the Page Editor preview and on `?embed=1` / Public Pages Open — only OS **prefers-reduced-motion** (or Subtle intensity for parallax) force them off. Scroll-linked parallax uses `useShowcaseScrollProgress` + `resolveShowcaseScrollRoot` so nested preview scrollports work.
- Gallery: tap/click opens shared **GalleryLightbox** via **Embla carousel** (`ShowcaseGalleryCarousel`) — no page-level horizontal scroll; **one image per slide** on all breakpoints and templates. **Aurora** + **Editorial** + **Haven**: prev/next + dot indicators + counter below the frame. **Monolith** + **Atlas** + **Verso** (single-photo fallback): inset arrows + dots inside the frame. **Verso** (≥2 photos): **scroll-pinned horizontal gallery** — sticky viewport, vertical scroll scrubs one full-bleed image at a time + progress bar; works in Page Editor / embed via `useShowcaseScrollProgress` (`pin` mode); **not** gated on Subtle intensity or reduced-motion (those only disable scrub spring). Carousel only when there is a single image.
- Deep links: `#amenities`, `#gallery`, `#host`, `#location`, etc. (native `scrollIntoView`; smooth when motion allowed)
- **Location:** all templates share `ShowcaseLocationSection` — **area line** (city, province, country deduped; parsed from saved `properties.address` when city/province fields are empty), **street/plus-code** from the address prefix when distinct, map via `ShowcaseMapEmbed` (**placeId** → lat/lng (incl. coords parsed from saved `mapsUrl`) → full formatted address; same resolution as property landing). **Directions** uses saved `mapsUrl` or pin. Host **body copy override** only when it adds info beyond the saved address. Location copy comes from **property settings**, not section body — preview mocks never inject lorem for Location; the placeholder banner only appears when property settings lack geo/address/locality (`hasShowcaseLocationContent`).
- **Preview placeholders:** in the Page Editor, embed (`?embed=1`), draft/unpublished preview, or `?preview=1`, empty visible sections are filled with lorem ipsum / stock gallery images via `showcaseSectionMock.ts` (**Location excluded** — uses property settings only). Affected sections show a compact palette-aware **“Renders test data”** badge inline beside the section heading (or Verso/Atlas chapter label). **Public Pages → Open** for Showcase uses `?embed=1` so hosts still see placeholders on a published page. Published live guest URLs (no embed/preview) do **not** inject placeholders — empty soft sections are hidden instead of rendering a heading-only band.
- **Reviews** (section id `testimonials`; default heading **Reviews**, not “Guest voices”): guest review cards from property reviews, or preview mock quotes in draft/editor — no separate section body blurb in preview. **Up to 4 reviews** shown per page (`showcaseTestimonialsForDisplay` in `showcaseSectionLayout.ts`). **Embla swipe carousel** (`ShowcaseReviewsCarousel`) on Aurora, Monolith, and Editorial — one full card per snap on mobile; prev/next, dots, and counter when multiple reviews; template-specific card styling (**Aurora** glass cards + quote icon; **Monolith** featured serif pull-quote; **Editorial** Cormorant cards with em dash attribution). **Haven** uses a centered two-up flex grid (odd last card centered on its row). **Verso** crossfade stage and **Atlas** stacked glass blocks use the same 4-review cap. Cards are never clipped in a raw horizontal scroll row.
- **Host:** replaces legacy house-rules section. Shows host avatar/logo, org name, verified badge, contact phone/email, social links (from app settings + guest contact), **View host** + **Contact** links.
- **Footer:** property logo/name (scroll to top) with **organization name** beneath the property title (falls back to location label only when org is missing), host name, contact block — **Plus Jakarta sans** at readable `text-base` (labels uppercase at `text-xs`); address, phone, email, socials (no “View host profile” / “Message host” links — those live in the Host section).
- Layout uses **container queries** (`@container` on `.showcase-scope`) so Page Editor mobile preview (~420px) reflows correctly — viewport media queries alone mis-size content inside the preview frame. **Verso** fluid display type uses **`cqw`** (container width), not **`vw`**, for the same reason.
- Body copy ≥16px; section titles sit close to content (`mt-5`)
- `?embed=1` / `?preview=1`: host preview when unpublished (placeholders + contained chrome). Canvas, parallax, and kinetic motion follow Style toggles (not forced off by embed). With `?embed=1`, global `guest-embed-preview` CSS clips document scroll (iframe thumbnails); showcase wraps content in a **`100dvh` overflow-y-auto** root so the page still scrolls when opened in a full browser tab from Public Pages.
- Unpublished + no preview: “Not available”

## Editor

- Route: `/org/:orgSlug/property/:propertySlug/public-pages/showcase/edit`
- Permission: `publicPages.showcase:edit`
- Plan: editor explore-open on every plan; save → `publicPagesAutosave` (Pro+); live guest URL → `propertyShowcase` (Pro+, non-dismissible blur overlay when denied)
- Controls: **template picker**, section reorder + visibility, copy/image overrides, columns, palette / typography / motion, click-section-in-preview → focus control
- **Template picker:** 3×2 grid of **live scaled mobile previews** (420px-wide frame, same pipeline as the editor preview) — one miniature render per template with current config, palette, copy, and media; thumbs are **inert** (no mobile menu / theme toggle / scroll root; section `id`s stripped) so hamburger and scrollspy stay scoped to the main Preview pane; motion/parallax/canvas toned down; `useDeferredValue` keeps typing smooth. **Clicking a template** scrolls the main Preview pane to the top (hero) so the new layout is visible immediately.
- **Section details** (all templates; fields vary by section via `showcaseSectionEditorFields.ts`): copy overrides prefilled with resolved preview text; edits persist only when they differ from baseline (clearing a field restores the property baseline for that field). **Hero** — **Above heading** (`Development` default when condo+residence / `Location` / `Custom` + text), heading, subheading, **single** hero photo picker, primary button. **Gallery** — heading, subheading, multi-select image slots. **About** — heading, subheading, body. **Amenities** / **Highlights** — heading, subheading, body, **Columns** (1–4). **Location** — **Under heading** (`Development` default when condo+residence / `Location` / `Custom` + text), heading, body (extra blurb; street/plus-code + map still come from property settings). **Testimonials** — heading + subheading (review cards come from guest reviews). **Host** — heading + body. **CTA** — heading, subheading, body, primary button. Hero/CTA **button label** + **Link to** (booking form, calendar, or custom URL) — Custom URL stays selected while typing; unfinished custom drafts are not saved. Image slots are **per section**: **Hero** picks one photo for the hero; **Gallery** multi-select only affects the gallery carousel. Empty Hero selection uses the first property photo; empty Gallery selection means **all** property photos for that section.
- **Style**: palette mode (default / brand / curated presets / from photos), accent (brand or **custom hex** — **Default** only), type scale, motion intensity; plus **only when the template uses them** — hero overlay, display font (Aurora), parallax (Aurora / Atlas), canvas background (all except Haven). Light/dark is the header theme toggle only.
- Header chrome: portaled **`position: fixed`** via `useShowcaseHeaderPin` (live → viewport; Page Editor / embed → preview-frame `getBoundingClientRect`, **kept in sync on nested and page scroll** via `observeShowcaseFrameRect`) so Admin `PageTransition` transforms, `@container`, and warm-tint `filter` cannot trap the bar. The Page Editor preview frame is a bounded `absolute inset-0` scrollport so guest content scrolls inside the phone/desktop frame instead of moving the header. Template-picker thumbs keep an in-flow decorative header. Heroes sit full-bleed under the bar; **eyebrow / above-heading copy** uses shared top inset from `showcaseHeroLayout.ts` (`pt-32`+ live, `pt-36`+ Haven floating capsule, same clearance in Page Editor) so sticky chrome never covers location/development lines. `.showcase-scope` also sets `scroll-pt-*` so in-page anchor jumps clear the header. Desktop and mobile both register the **bordered frame** as the scroll root (padding sits outside) so sticky chrome stays flush inside the frame instead of pinning in the gray gutter. Aurora **section progress rail** is live-site only (hidden in editor/embed so it never overlaps dashboard UI)

# Scripts

Repo automation — local dev, data sync, deploy, integrations. Run from **repo root** unless noted.

## Layout

```
scripts/
  marketing/     Host marketing asset generators (Edge TTS narration)
  dev/           Local Supabase + edge functions env
  data/          Prod → local Postgres sync
  deploy/        Linked Supabase project deploy
  migrate/       Legacy → mt-prod data migration (Phase B — stub)
  preview/       Email template preview from DB
  docs/          One-off docs/ vault migrations
  performance/   Production-readiness baselines, bundle budgets, image/chunk audits
```

## Performance (`scripts/performance/`)

Tooling for [`docs/workflow/planned/production-readiness-checklist/`](../docs/workflow/planned/production-readiness-checklist/README.md) doc 00 (baseline & budgets), 01 (code splitting), 02 (minify), and 03 (lazy loading).

**Dependency audit (doc 05):** `bun run audit:deps` runs `knip` (report-only, `--no-exit-code`) against the whole repo. Not wired into CI — this codebase has several patterns knip's static-import analysis cannot see (binary-path invocation, ambient `@types/*` packages, ESLint plugins referenced by string name, ~1000 files under `.agent*/` invoked dynamically by AI-tooling skills, and a Deno edge-function tree it doesn't analyze at all), so its raw output has a high false-positive rate here. Always hand-verify a finding with a grep for real usage before removing anything — see the worked example in `docs/workflow/planned/production-readiness-checklist/05-unused-dependencies.md`, where 7 of 9 flagged dependency findings turned out to be false positives.

Run `node scripts/performance/<script>.mjs` directly, or via the `bun run perf:*` aliases above.

**`lighthouse-routes.mjs` troubleshooting:** the script runs a sanity probe before auditing any route and fails fast with a clear message if headless Chrome cannot paint at all (`NO_FCP` on the very first page) — this means the current environment has no real display server available to Chrome (seen in sandboxed CLI/container environments; look for `CVDisplayLinkCreateWithCGDisplay failed` in Chrome's own stderr). That is an environment limitation, not a bug in this script or the app — re-run on a developer laptop or in GitHub Actions (which already installs a working headless Chromium via `bun x playwright install chromium`). If a route instead reports `n/a` metrics with an "incomplete trace" warning after the sanity probe passed, a prior run may have left orphaned Chrome/`vite preview` processes competing for system resources — check `ps aux | grep -i "chrome\|vite preview"` and kill anything stale, then re-run. The script cleans up its own Chrome/preview processes on a normal exit, on `SIGINT`/`SIGTERM`, and via a process-group `SIGKILL` fallback (chrome-launcher's own `.kill()` was observed to leave GPU-helper children behind on macOS) — a `kill -9` on the script's own PID bypasses all of that and can still orphan children.
